# Audit 08: WGSL and 0.1.0

## Outcome

Production WGSL is implemented. The latest ARM candidate is built from
`8b0fe81f5f6869d1ced67fc3cd1dbf6d366dae36`, executable SHA-256
`bdfc9f1d978cf052e01db97d69b1d61c1ad9cc073b7691a82e2cb2d90baaa141`.
Default/editor each pass 220 tests. Installation and the recorded native
AE 2026 **26.3x87** acceptance subset are complete: the combined checker passes
**558/558**, independent aerender exits 0 with **24 physical PSD frames**, and
real GUI Language Undo/Redo, precise fresh defaults, CR source authoring and
Full/Half/Quarter viewports pass. The installed executable remains bdfc before
and after rendering. [Build evidence](evidence/wgsl-010-20260908/build-bdfc/README.md),
[final host evidence](evidence/wgsl-010-20260908/host-bdfc/README.md).
The final-candidate ZIP is assembled and its 287 internal-manifest files,
arm64 signature and unchanged executable/PiPL identities pass extraction
verification. Source/archive privacy and governance scans pass. Push, tag,
publication and download verification remain pending.

The first candidate [91c8 failed Language Undo](evidence/wgsl-010-20260908/host-91c8-undo-failure/README.md)
after 217 numerical assertions passed. Its replacement
[661e passed Language Undo/Redo](evidence/wgsl-010-20260908/host-661e-authoring-failure/README.md)
and preserved keys, but manual editing exposed bare-CR annotation loss and
short-name suffix corruption. The bdfc host run verifies both repairs. These earlier
candidates remain retired; their failures are retained below as history.

Source-expression single Undo still fails because of the pre-existing
background publication mechanism. The user explicitly accepts disclosure
in 0.1.0 and a separate future repair under
[ADR-0045](../adr/0045-010-source-undo-release-boundary.md).
This is an accepted limitation, not a passing Source Undo test. Verification
authority remains [TR-WGSL-002](../TEST_MATRIX.md#tr-wgsl-002--production-wgsl-and-host-integration-010)
and [TR-REL-010](../TEST_MATRIX.md#tr-rel-010--010-publication).

## Code paths and contracts

[ADR-0044](../adr/0044-wgsl-and-010-release.md) activates stable ID 2, appends
WGSL after the unchanged GLSL default, and specifies the release subset.
[wgsl.rs](../../src/frontend/wgsl.rs) parses original WGSL IR;
[shared.rs](../../src/frontend/shared.rs) reflects the parameter/annotation
model shared with GLSL. Graph execution, SPIR-V emission, upload and renderer
remain shared; there is no generated GLSL schema in this compiler.

Unsupported stages, entry/IO shapes, resources, address spaces, bindings,
overrides and optional f16/subgroup capabilities are rejected. The uniform
head remains at 0/8/12; native offsets and explicit padding are reflected,
with a 64 KiB limit before GPU allocation. Envelope `@@` escaping is unchanged.
E21 identifies WGSL parse/validation errors; E18/E19/E20 retain their meanings.
Diagnostics report pass-local locations and the original body-start line,
without presenting unescaped byte columns as original envelope columns.
Snapshots retain exact source, Language ID and binding plan; no schema change.

## Findings and failures

The final bdfc run's first scripted Gradient assignment failed because the
parent/child color controls were hidden. Readback recorded partial GLSL
Layer/Path assignment and untouched gradient colors. Opening the GLSL and
WGSL Effect Controls and expanding Main/Gradient 01 exposed the two active
color rows; a newly tagged script then passed the original value/pixel
assertions. The initial failure and recovery remain in the host evidence.
This is a passing resource run with a UI initialization prerequisite, not
proof of fully headless first-time Gradient assignment.

The [first production comparison](evidence/wgsl-010-20260908/gpu-first-instrument-failure/result.json)
failed because independently loaded GLSL lacked the parameter annotations
supplied to WGSL. The historical spike had passed shared annotations externally.
Supplying identical metadata yielded zero-error pairs with the same
runner/source identities. This was an instrument correction, not a runtime
fix; failing outputs remain preserved.

The examples' [log](evidence/wgsl-010-20260908/examples/renders.log) preserves
an initial sandbox failure to enumerate Metal, followed by successful runs
with GPU access. Their 8-bpc multipass output differs from float because of
intermediate clipping/quantization, with a recorded maximum difference about
0.0284. The limited mean-error check does not claim per-pixel depth equivalence.

The [independent review](evidence/wgsl-010-20260908/independent-review/review-notes.md)
found no new production defect and verified extraction of the original GLSL
reflection logic. A test-only escaping helper had a limitation for future
indented fixtures; this was not a production parser failure. Review and three
layout probes do not constitute exhaustive compiler fuzzing.

Publication review found historical third-party details in ADR-0033 and an
optional comparison script. Visible redactions follow ADR-0036; the script
now requires an explicitly supplied reference name. The dated
[preflight](0.1.0-release-preflight.md) records this and remaining publication
checks. Previously published history cannot be recalled.

## Known limitations and residual risks

The recorded bdfc AE 2026 subset passes with two explicit boundaries:
Source-expression single Undo remains the known FAIL accepted by ADR-0045,
and initial scripted Gradient color assignment needed the UI initialization
described above. Authors should keep previous source externally and restore
that text explicitly. Passing Language Undo/Redo is not Source Undo evidence.

Windows 0.1.0 artifacts and Windows/DX12 acceptance remain NOT_RUN. Other AE
years, Intel/Rosetta and cross-GPU bit identity are not granted by these
results. The candidate is ad-hoc signed, not Developer ID signed or notarized;
the optional gradient editor is disabled in the release flavor. The assembled
final-candidate ZIP is **3,563,347 bytes**, SHA-256
`f2fffc1808727231db8a713cddf024cbcf0e55a7f1064beff6d8897a129dcc3d`, at
`scripts/out/010/release-bdfc-final/DynamicFX-0.1.0-macos-arm64.zip`.
Packaging preserved the accepted bundle; extraction verifies 287 manifest
files, executable mode, arm64 signature and unchanged executable/PiPL hashes
in the [final package record](evidence/wgsl-010-20260908/package-bdfc/README.md).
Final source/archive privacy and governance checks pass; the package record
retains the precommit scan snapshot. Old 91c8 archive checks do not certify this ZIP.
No push, tag or release is published; post-download verification and the
actual iOS 27 Siri implementation have not started.

## Decision changes

ADR-0044 supersedes feasibility-only scope with production WGSL and an
authorized macOS-first 0.1.0 release. It does not add arbitrary WebGPU resource
interfaces, change the persistent schema, or grant untested host support.
ADR-0045 accepts the disclosed Source-expression single-Undo limitation for
0.1.0 only and schedules its architecture repair separately; it does not waive
the remaining authoring, host, identity or publication checks.
Actual iOS 27 Siri implementation begins after release publication.

## Reproduction

Use the frozen compiled-source revision, retained lockfile and linked
fixtures. Run scripts into fresh output directories to preserve earlier
results. The evidence [README](evidence/wgsl-010-20260908/README.md) explains
float decoding and manifest verification. Native installation uses
`scripts/macos.py` against one explicit AE year; verify the installed hash
before host tests. Do not rebuild or re-sign accepted bytes when assembling
the eventual release archive.
