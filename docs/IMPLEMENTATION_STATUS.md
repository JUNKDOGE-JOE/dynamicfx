### ADR-0037 valid-range fix — HOST-VERIFIED, awaiting 0.0.4 release (2026-08-19)

**Defect** (public issue [#5](https://github.com/JUNKDOGE-JOE/dynamicfx/issues/5); reported by the user as "the upper limit seems locked at 1.x"): every Float pool value above 1.0 reached the shader as exactly 1.0 (the `1.004` readings are 8-bit quantisation of 1.0), negatives floored at 0.0, Integer values capped at 10, whatever `@param min:/max:` declared — UI showing the intended value, render not using it. Measured 2026-08-15/16 on AE 2026 with the 0.0.3 artifact by pixel readback; the shipped `examples/thermal.glsl` (`glow` default 1.2) and the README's `speed min:0 max:4` example were affected, and shaders written against 0.0.3 worked around it by declaring everything `min:0 max:1` and remapping inside. Root cause is the host contract, not the plug-in's read/pack path: `PF_UpdateParamUI` can change only `slider_min/slider_max/precision/display_flags`; the valid range registered at `PARAMS_SETUP` (`0..1` Float, `0..10` Integer) is what AE clamps rendered values to. TR-M2-002/003 never probed a float above 1, an int above 10, or a negative.

**Decision:** [ADR-0037](adr/0037-pool-valid-range-and-slider-range.md) (Accepted 2026-08-19) — Float and Integer pools register a wide valid range (±10⁹) at `PARAMS_SETUP`; `@param min:/max:` is the slider range; the runtime never clamps.

**Code-complete + host-verified 2026-08-19** ([TR-0037-001](TEST_MATRIX.md#tr-0037-001--pool-valid-range-float1-negative-int10) `PASS` on AE 2025 and AE 2026): `POOL_FLOAT_VALID_RANGE` / `POOL_INT_VALID_RANGE` + slider defaults as named constants in [`src/host/params.rs`](../src/host/params.rs), used by `setup()` and pinned by `pool_valid_ranges_are_wide_symmetric_and_exact`; `configure_slots` ([`src/lib.rs`](../src/lib.rs)) writes the declared range to the slider fields (and valid fields — a **measured no-op**: `setValue(0.3)` on a `min:2` slot was accepted on both host years) and resets an un-ranged binding to the display default + wide valid range; 129 unit tests green, release build warning-free, governance `PASS`. Host: `f003h` renders the unclamped values (`rgb(51,51,153)`/`rgb(191,153,204)` where 0.0.3 gave `rgb(1,128,26)`), thermal's default palette rendered for the first time (glow=1.2), and the M2 + M3 batteries stayed green on both years. Docs updated: README `@param` table and a note under *Parameter types*; skill `SKILL.md`/`reference.md`. Public issues [#1](https://github.com/JUNKDOGE-JOE/dynamicfx/issues/1) and [#2](https://github.com/JUNKDOGE-JOE/dynamicfx/issues/2) were answered and closed as shipped in 0.0.3 the same day; new [issue #5](https://github.com/JUNKDOGE-JOE/dynamicfx/issues/5) tracks this fix.

**Exit:** host verification is done; what remains is the 0.0.4 release (package the verified `BFE1AB9F…` artifact per the TR-REL procedure — never rebuild between host verification and packaging).

### Recorded, not scheduled

- **Canvas expansion beyond the layer frame — recorded 2026-08-21 (field question, AE 2026; [TR-BOUNDS-001](TEST_MATRIX.md#tr-bounds-001--shader-canvas-is-the-layer-frame-field-observation); public issue [#8](https://github.com/JUNKDOGE-JOE/dynamicfx/issues/8), enhancement).** The shader canvas is the layer's own frame by contract ([ADR-0011](adr/0011-shader-abi-v1-core.md) §5; `src/lib.rs` `Command::SmartPreRender` checks out `0,0,width,height` of the layer and declares `max_result_rect` = that frame; the PiPL sets no `PF_OutFlag_I_EXPAND_BUFFER`), so a shader that paints beyond its source — glow, halo, shadow, displacement overshoot — is clipped at the layer bounds, and an upstream buffer-expanding effect (Grow Bounds) does **not** enlarge the canvas: measured pixel-identical to the plain instance on the 0.0.5 artifact. Not a defect, not a shader-authoring error; a missing feature. The user-side answer is a padded precomp (now documented in the `dynamicfx-shaders` skill, with the `examples/apple-thermal.glsl` case as the worked example). A runtime implementation is ADR-sized: an explicit, stable expansion parameter (new persistent slot → [ADR-0013](adr/0013-paramid-grammar-and-pools.md) topology), the `u_resolution`/`v_uv` canvas definition and `input` placement ([ADR-0011](adr/0011-shader-abi-v1-core.md) §5, [ADR-0029](adr/0029-logical-resolution-abi.md)), [ADR-0030](adr/0030-layer-input-parameters.md) §4 comp-space alignment of layer inputs, temporal history extents ([ADR-0023](adr/0023-temporal-seek-reset.md)/[ADR-0024](adr/0024-history-format-policy.md)), extents in the identity/cache keys ([ADR-0007](adr/0007-identity-and-cache-boundaries.md)/[ADR-0017](adr/0017-hash-domains.md)), and the SmartFX `max_result_rect`/`EXPAND_BUFFER` protocol ([TR-M7-004](TEST_MATRIX.md#tr-m7-004--roi-final-pass-delivery)). A request-derived canvas was rejected on sight: AE's ROI request varies per render, and a canvas that moves with it breaks WYSIWYG and every `uv`-space shader; the stable alternative signal is the upstream extent (`max_result_rect`) in the `PF_CheckoutResult` that `checkout_layer` already returns and the code currently discards (`Ok(_)`) — which is also exactly why an upstream Grow Bounds is invisible today (the checkout rect is overwritten with the source layer's `in_data.width/height`, so the added margin is never read). Evidence: [`audits/evidence/field-20260821-layer-bounds/`](audits/evidence/field-20260821-layer-bounds/README.md).
- **Float/Integer pool render clamp — recorded 2026-08-19, promoted to active work the same day.** See *ADR-0037 valid-range fix — ACTIVE* above; the defect had lived only in issue #2 of the archived `dynamicfx-dev` repository (frozen, read-only) and is now public issue #5.
- **Harness proxy imprecision (pre-existing, found 2026-08-15).** Several M1/M3 evidence scripts log `token_nonzero=(value > 0)` as a stand-in for "published". That has always been imprecise — every published diagnostic (token state `0b10`) is non-zero too, so an `Invalid` outcome scores as 1 — and E53 adds one more state to the same weak predicate. The exact test is `% 4 === 1` (Active). Only the one site that *gates* behavior was corrected (`scripts/m7/m7bench.jsx`); the logging sites are untouched because the scenarios they cover do not reach an Invalid state. Sweep the remaining sites when those suites are next edited.
- **Point 3D default units are unmeasured (recorded 2026-08-16).** Whether PF reads a Point 3D's *declared* `x/y` default as a percentage of the frame (as Point 2D's is) or as absolute pixels is not established — the SDK header is not vendored with the crate, and the host leg sets the value explicitly, so it settles the *value* encoding (confirmed normalized in x/y, pixels in z) and not the default's units. Both readings put the shipped default somewhere visible, so it is safe unresolved.
- **Growth-pool slots show a generic label (measured 2026-08-16, AE 2025 and 2026).** Layer, Gradient, Point 3D and Path rows display their pool name instead of the shader's `label:`, while every V1 kind displays it correctly — from one shader, in one read, and unchanged a full idle window later, so it is not refresh timing. `PF_UpdateParamUI` reports success and AE ignores the name. The AEGP second route (`AEGP_SetStreamName`, the same trick that fixes the Hidden flag for `PF_Param_ANGLE`) **was implemented and hung the host** — it is documented as Undoable and froze AE before one leg completed, so it was reverted rather than shipped. Cosmetic only: value, keyframes, identity and rendering are unaffected. Reopen when the undo-group requirement is understood.
- **A path input on an adapter without `FLOAT32_FILTERABLE` is untested (recorded 2026-08-16).** The verified adapter (RTX 5080, DX12) has the feature. Without it the path texture is refused and the zero texture binds with a log line, which is the designed behaviour but has never been executed.
- **Path tangent semantics are unmeasured (recorded 2026-08-16).** Whether `PF_PathVertex`'s `tan_in_*`/`tan_out_*` are offsets from the vertex or absolute handle positions is not established. `src/path.rs` normalizes them either way and says so; the TR-0035-001 host leg settles it, and no shader should be told which reading applies before then.
- **Point parameters have no usable starting position (found 2026-08-15 while authoring `examples/orb.glsl`).** `vec2` binds to a Point2D pool slot whose fixed default is (50, 50) *pixels* — the top-left corner of any real comp — and annotation defaults for points are still v1-rejected, so a shader cannot ship a sensible one. The orb example avoids `vec2` for this reason. Closing it needs the same AEGP TwoD stream-value plumbing already listed for point defaults; a normalized-default convention would also have to be decided.
- **Public README version is stale**: it still reads `0.0.1 — pre-release` in both this repo and the public one, though 0.0.2 shipped 2026-08-14. Correct it as part of the 0.0.3 release step.
